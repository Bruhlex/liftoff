Liftoff decompiler for obfuscator.io's VM

Liftoff turns JavaScript protected with the Virtualization option of obfuscator.io back into readable JavaScript. Files without a VM are deobfuscated with webcrack instead. Everything runs in your browser; the file is never uploaded.

How it works

    
    
      
  1. Normalize the file with webcrack
        (string arrays, wrappers, formatting).
    2. 
      
  2. Locate the interpreter by its shape and infer the role of each array
        (operand stack, registers, bytecode).
    3. 
      
  3. Map every handler to an instruction with about 130 rules; an unknown
        handler is explained by running one dispatch step instead of guessing.
    4. 
      
  4. Load the bytecode with the build's own loader.
    5. 
      
  5. Lift the bytecode with a symbolic operand stack and put the recovered
        functions back where they were called.
    6. 
    

    
The page reports how much of the bytecode came back as real code. An instruction counts as
      not recovered when its opcode could not be identified or when it had to be emitted as a
      placeholder call such as __UNKNOWN_12(...). A file without an obfuscator.io
      virtual machine is passed through webcrack only, which undoes string arrays, control-flow
      flattening and similar transformations where it recognises them.

    
Nothing about a build is hard-coded: opcode numbers, byte format, alphabet and dispatcher
      are inferred from each file. The decompiler was tested on 136 builds, including 120 builds of
      programs of up to 900 lines under eight option sets, and every decompiled program prints the
      same output as its obfuscated build.

    
Supported versions

    
Written and tested for the VM mode of obfuscator.io's hosted service, using builds made
      with the free tier of the dashboard:

    
    
      
  • 16 builds from July 2026, made with the earlier code generator;
    • 
      
  • 120 builds made on 29 September 2026 with version 8.0.6 and the
        VM Low preset, alone and combined with string arrays, control-flow flattening,
        expression obfuscation, raw output and the Node target.
    • 
    

    
The separate hardening options of the virtual machine (for example encoded jumps,
      stateful opcodes or a split dispatcher) were not part of these builds and are untested.
      Later versions of the obfuscator may change the instruction set; unknown handlers are then
      reported instead of guessed, and the recovery figure drops below 100 %.

    
Scope and limits. The result is a readable program that
      behaves like the original, not the original source: local names, comments and the choice
      between equivalent forms are lost in compilation. Only obfuscator.io's VM mode is supported.
      To read the bytecode, the decompiler runs the file's own loader code inside a Web Worker of
      this page, with network and DOM globals hidden. This is not a security sandbox; only decompile
      files you are willing to run.
